うまくいかないときは、まず**どこまで届いているか**を切り分けます。

1. `log` シートに行が増えている → LINE から GAS までは届いています。GAS の中を疑います
2. 増えていない → Webhook の設定か、デプロイを疑います

GAS の左メニュー「実行数」を開くと、`doPost` が動いたか、どこでエラーになったかも見られます。

## Webhook の「検証」が失敗する

- ウェブアプリの URL の末尾が **`/exec`** になっているか（`/dev` ではないか）
- デプロイ設定の「アクセスできるユーザー」が **全員** になっているか
- 「デプロイを管理」のアクティブなデプロイの URL と、Webhook URL に登録した URL が同じか
- 結果が **「200以外のHTTPステータスコードが返されました。(302 Found)」** なら、`doPost` に `return ContentService...` が残っていないか

:::message alert
**302 になる理由**: `doPost` が何かを `return` すると、GAS はその中身を返すために `script.googleusercontent.com` へリダイレクトします。LINE の検証はこれを失敗として扱います。**`return` を消して何も返さないようにすれば、検証は「成功」になります。**（[Step1 の Qiita 記事](https://qiita.com/4geru/items/5e5e23d6540beed4adc0)のコードも、何も返していません）
:::

直ると、次のように「成功」と出ます。

![LINE Developersの「Messaging API設定」画面。Webhook検証の結果が「成功」と表示され、Webhookの利用がONになっている](/images/nara-line-location-log-handson/01-03-04-webhook-verify.png)

## コードを直したのに、動きが変わらない

**保存しただけでは LINE 側に反映されません。**「デプロイ」→「デプロイを管理」→ 編集（鉛筆アイコン）→「バージョン」を **新バージョン** にして「デプロイ」を押します。詳しくは [Step1 の Qiita 記事](https://qiita.com/4geru/items/5e5e23d6540beed4adc0)の「コードを変えたのに反映されない」を見てください。

## `スクリプトプロパティに ... を設定してください` と出る

スクリプトプロパティの登録漏れです。この本で使うのは次の3つです。

| プロパティ | 使う章 |
| :--- | :--- |
| `LINE_ACCESS_TOKEN` | [Step1 の Qiita 記事](https://qiita.com/4geru/items/5e5e23d6540beed4adc0) |
| `DRIVE_FOLDER_ID` | [写真をアップロードする](./03-01-photo-upload) |
| `LINE_BASIC_ID` | [QRコードを作る](./03-06-qr-code) |

## ボタンを押したら「もう一度位置情報を送ってください」と出る

Bot は、押されたボタンが**いま進んでいる会話のもの**かを確かめています。次のどれかなら、この返事になります。位置情報を送り直せば、最初からやり直せます。

| 原因 | よくある場面 |
| :--- | :--- |
| 位置情報を送ってから30分たった | 休憩のあとにボタンを押した |
| 同じボタンをもう一度押した | 返事が遅くて、選択肢を二度押しした |
| 前に送った場所のボタンを押した | トークを上にさかのぼって、古いボタンを押した |
| `state` シートに自分の行が無い | 位置情報を受け取ったときの `setState` まで届いていない |

断ったボタンは `postback` シートに残りません（`log` シートには残ります）。

## 「質問が見つかりません」と出る

`question` シートが無いか、空です。エディタから `setupSheets` を実行してください（[質問をシートで増やす](./02-03b-question-sheet)）。実行後に位置情報を送り直せば、問1から聞かれます。

## 「登録しました」と出たのに `submission` に出ない

`submission` に出るのは、**今ある質問すべてに答えた場所だけ**です。

- 質問を後から足した → 過去の登録は新しい質問に答えていないので、いったん表から消えます。足した行を消せば、また出てきます
- 回答の途中で `question` を変えた → 登録が途切れることがあります。位置情報を送り直してください
- `submission` シートが無い → `setupSheets` を実行していません

## `answer` や `submission` に `#REF!` と出る

数式の結果を広げる先のセルに、値が入っています。`answer` と `submission` は数式だけでできているシートなので、A1（`answer` は H1 も）以外のセルに書いた値を消してください。どこに書いたか分からなければ、シートごと消して `setupSheets` をもう一度実行しても大丈夫です。

## GPS 検索で「登録された場所がまだありません」しか出ない

検索するのは `submission` に出ている場所（全問答えて登録した場所）だけです。位置情報を送っただけの場所や、検索に使った場所は入りません。`submission` に行があるか見てください。`setupSheets` を実行していないときも、この返事になります。

## 写真を送ったのに、カードや地図に写真が出ない

次の順に確かめてください（[写真をアップロードする](./03-01-photo-upload)）。

| 確かめること | 見方 |
| :--- | :--- |
| 「この場所を登録する」を押したあとに送ったか | 押す前や、問1に進んだあとに送った写真は、`photo` シートに残るだけで、場所にはつきません |
| `location` シートの H 列（写真URL）に値が入っているか | 空なら、写真が場所にひもづいていません |
| Drive の共有が「リンクを知っている人」か | 写真を保存するコードを書き換える前に送った写真は、共有が「自分だけ」のままで、画像が表示されません。送り直してください |

## リッチメニューの設定でエラーになる / 文字が□になる

`setupRichMenu` が、画像を読む URL（`RICH_MENU_IMAGE_URL`）から取れていないときは、エラーで止まります。URL をブラウザで開いて、画像が表示されるか確かめてください（[リッチメニューを作る](./03-03-rich-menu)）。仮画像の `placehold.co` は日本語の文字が出ず、□になります。自分で画像を作るときは、文字を入れた PNG を用意してください。

`setupRichMenu` は、最初に今あるメニューを全部消します。メニューが増えて困ったときは、もう一度実行すれば、1つに戻ります。

## 会社の PC で進めている

組織の設定で、GAS のウェブアプリを「全員」に公開できないことがあります。うまくいかないときは、個人のアカウント・個人の PC がおすすめです。
